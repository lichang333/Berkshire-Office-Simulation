## 格式

```
## YYYY-MM-DD · <事项>
- **裁决**:批准 / 否决 / 归入太难筐 / 加价再谈
- **金额**:$X [演练](占可动用弹药 Y%,取自 float.md 期初表)
- **理由**:三句以内
- **对照的机会成本**:我放弃了什么;写出 hurdle.md 的行名和数值
- **可证伪的判断**(判断卡 1–3 张,一行一张):
- J-YYYYMMDD-n｜命题：<某事件会发生>｜判定：<看哪个文件或哪类回件>｜截止：YYYY-MM-DD｜p=0.xx
- **谁负责**:姓名 + 他不需要向我汇报什么
```

> 判断卡一行一张,全角竖线分隔;p 取 0.05–0.95,步长 0.05,写下不改。证伪席的卡编号 J-YYYYMMDD-S,由 chairman 原样抄进条目。卡上的截止日就是复核日,新条目不再单写「复核日期」行。
> 写下可证伪的判断只是一半,另一半是到期打脸。复核记录追加在原条目下方,一张卡一行:
> `- 复核 YYYY-MM-DD · J-YYYYMMDD-n：发生 / 未发生 / 作废（原因码）`;判不了但还有指望的,写 `顺延至 YYYY-MM-DD（原因码）`。
> 原因码只有四个:无来件 / 证据不足 / 运行断档 / 条件变更。顺延只许一次,第二次到期仍判不了即作废。
> 复核日落在周六、周日的,顺延到下一个工作日(周一)。
> 旧格式条目(带「复核日期」行)保留原样,复核照旧写在条目下方:`> 复核 YYYY-MM-DD:对 / 错 / 顺延至 YYYY-MM-DD(原因码)。一句话:当时的判断错在哪 / 对在哪。` 脚本把它们登记为 L-<条目日期>-n,只追踪逾期、不计分。已写入的历史条目一律不改(2026-10-24 是周六,按 2026-10-26 算)。

## 2026-08-09 · 流程性决策:初筛把未核实项藏进脚注(deal-screener)
